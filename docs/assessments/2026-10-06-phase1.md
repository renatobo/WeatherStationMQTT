# Phase 1: reliability and correctness

Date: 2026-10-06. Version: [v0.2.0](https://github.com/renatobo/WeatherStationMQTT/tree/v0.2.0). Baseline: v0.1.0.

## Implementation

- MQTT is serviced on every main-loop iteration. Reconnect uses one Wi-Fi-gated attempt with exponential backoff capped around 30 seconds plus up to 250ms jitter. The existing ESP8266 WiFiClient timeout covers DNS/TCP/write waits at 250ms; PubSubClient packet/CONNACK waits are limited to 1 second per library wait. These are bounded synchronous operations, not a new asynchronous transport.
- DHT22 is configured explicitly. Each minute starts a cycle of at most three reads, spaced by 2.5 seconds; library waiting is disabled. Only finite, in-range, coherent temperature/humidity pairs are accepted. Invalid reads clear current validity while retaining last-valid acquisition time for diagnosis.
- Sensor acquisition timestamps are used by HTTP and MQTT. Values and labels share the METRIC policy. The semicolon schema, device identifiers and topics are retained; timestamps remain in the existing local DST-adjusted convention.
- Timestamp and MQTT formatting use actual buffer sizes and reject truncation. Both clock styles use bounded formatting. MQTT packet size is checked before queueing. Display/HTTP values become unavailable when the latest read failed or the valid sample is over two minutes old.
- A fixed-size pending slot retains the latest scheduled pair. Successful halves are not repeated after partial failure; failed halves retry at most once per second. New scheduled pairs replace older pending data; data expires five minutes after acquisition. This is RAM-only, QoS0 buffering: it does not survive reboot and does not acknowledge durable ingestion.
- HTTP/OTA service is independent of the UI budget; idle display delay is capped at 5ms. Presence timer callbacks only set flags; display/socket work runs in the main loop. OTA progress handles zero/small totals safely.
- /info adds freshness/error counters, connection/publication counts, skipped schedules, pending replacements/expiry and maximum MQTT service gap.

## Host and build verification

The shared policy code was tested using clang++ C++11 with -Wall -Wextra -Werror, AddressSanitizer and UndefinedBehaviorSanitizer. Checks cover exact timestamps, undersized buffers, maximum accepted identifiers and rejection beyond the limit, 12/24-hour clocks, metric/imperial values, nonfinite/out-of-range readings, startup spacing, three-attempt cycles, no repeated reads between cycles, millis rollover, partial publication without resending a successful half, TTL expiry, and a fake-clock simulation of 30 minutes without a broker followed by 10 minutes without Wi-Fi.

The simulation exercises the actual firmware scheduling/pending policies with fake clients. Its HTTP/OTA tick counters prove policy code does not block; they do not validate real SDK timing, physical RF outages, TCP-blackhole behavior or hardware sensor removal. Those tests were not performed on production devices. No broker, collector, eero or Wi-Fi settings were changed.

All six profiles passed. A temporary metric/24-hour profile also passed. Application formatting warnings are eliminated. Pinned dependencies still emit simpleDSTadjust operator-precedence and PubSubClient signedness warnings; neither is hidden or suppressed. CodeRabbit is unavailable; source review was manual.

## Recovery and remaining limits

The v0.1.0 workshop/office recovery images and manifests remain in .recovery/v0.1.0/. The v0.2.0 canary archive contains all six BIN/ELF images, source snapshots, config and SHA256 checksums; live MD5 read-back identifies the uploaded images. Recovery images embed private configuration and were not attached publicly. Physical serial recovery has not been rehearsed.

The optional weather library still has synchronous HTTP and no reliable outer deadline. Weather refresh is deferred while MQTT is disconnected, and its artificial 1-second delay was removed; a weather-side indefinite stall remains possible and is Phase 2 work. This release does not claim every possible main-loop stall is resolved.

Authentication/TLS, signed updates, durable acknowledgements, historical reset counters and a 72-hour soak remain later-phase work. Observe the new counters and correlate MQTT with storage before expanding the rollout beyond workshop and office. Printer3d was compiled only; its AHT10/DHT configuration mismatch was not changed or flashed.
